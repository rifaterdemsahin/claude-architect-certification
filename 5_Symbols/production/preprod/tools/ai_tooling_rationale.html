AI Tooling Rationale

The right model for the right job

No single AI does everything well. This is the working split behind the Claude Architect Certification build — each tool owns the job it's genuinely best at, so cost, quality, and speed all stay where they should.

🧠 The principle

Treat each model as a specialist, not a generalist. Image generation, long-context ingestion, precision code edits, repetitive error-fixing, and repo-wide refactoring are different problems with different cost/quality profiles. Routing each task to the tool built for it is faster, cheaper, and produces better output than asking one model to do all of it.

🛠️ The split

Gemini
Google · long-context multimodal
Image creation & bulk context load

Owns the two jobs its huge context window and native image model do best: generating course visuals (diagrams, hero art, infographics) and ingesting whole repos / docs / PDFs at once to summarise, index, or answer across them. When you need to "dump everything in and ask about it", it goes here.

✨ Create · Ingest
DeepSeek
via Kilo CLI · VSCode inline
Precision code generation in the editor

Run inline inside VSCode through the Kilo harness for fast, cheap, token-efficient code completion and surgical edits. It's the daily-driver "cut code" model — strong at focused generation (functions, SQL, configs) at a fraction of the cost of the bigger agents. Nothing long-horizon; just sharp, local edits where you're already typing.

✂️ Cut code
Z.ai (GLM)
long-context · runs the fix agent
Solving errors with the fix agent

Powers the autonomous error-loop fix agent on known / repetitive tasks — the class of error we've seen before and have a reliable pattern for. Its long context ingests the log + file + issue at once and ships a scoped, verifiable patch cheaply and predictably. It's the workhorse for closing axiom-error issues that don't need human judgement.

🔧 Fix · Automate
Claude Code
Anthropic · agentic, repo-aware
The coding map & refactors

Owns the high-leverage, high-judgement work: building and maintaining a coding map of the whole repo, then executing large refactors across many files at once while keeping behaviour consistent. When a change needs real planning — moving abstractions, untangling coupling, restructuring a module — this is where it goes.

🗺️ Map · Refactor

📊 Decision matrix

ToolOwnsUse when…Don't use for
✨ Gemini Images & bulk context You need a visual, or to load an entire repo/doc and ask across it. Fine, multi-file code refactors.
✂️ DeepSeek (Kilo + VSCode) Inline code edits You're in the editor and want a fast, cheap, focused code completion. Repo-wide planning or open-ended architecture decisions.
🔧 Z.ai / GLM The fix agent An error matches a known pattern and can be auto-fixed and verified. Novel bugs needing real diagnosis or design judgement.
🗺️ Claude Code Coding map & refactors A change spans many files and needs planning + behaviour preservation. Throwaway one-liners — overkill on cost.

💡 Why split at all?

Using one model for everything means overpaying on cheap jobs and under-thinking on hard ones. Gemini absorbs context and makes pictures; DeepSeek cuts code cheaply where you're typing; Z.ai grinds through the known-error backlog autonomously; and Claude Code holds the map and does the refactors that actually move the architecture. That division is what keeps this project fast, cheap, and high-quality at the same time.
